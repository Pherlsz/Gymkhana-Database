**Mudança:**
- Definir altura de linha fixa p/ `.dl .v` e `.dl .v.editing input` (ex.: `min-height: 2.4em`, mesmo padding vertical) para que ativo e inativo ocupem o mesmo espaço.

- Estado vazio ("adicionar…") mantém itálico `--ink-3`, mas com a mesma altura de linha.

**Validação:** screenshot com 1 campo em edição + vizinhos; nenhum salto de layout ao focar/desfocar.

## Tarefa 4 — Catálogo real do DB: tipos e campos por documento/conta

**Problema duplo:**
(a) o mock INVENTA tipos que não existem no DB (select de contas tem Gás/Telefone/Outro; select de docs tem "Outro") — o DB tem exatamente 21 tipos de documento e 3 tipos de conta (Anexo A);
(b) o mock trata todos os tipos igual (nome + observação), mas o DB define campos próprios por tipo em `custom_field_definitions`.

**Mudança (dados — espelhar o DB no script):**
```js
// Fonte: database/migrations/021, 024, 031, 032 (document_types) e 027 (bill_types + custom_field_definitions)
var DOC_TYPES = [ /* 21 entradas: key, label, regex? (cpf/pis: ^[0-9]{11}$), fields[] */ ];
var BILL_TYPES = [ /* exatamente 3: energia='Conta de luz', agua='Conta de água', internet='Internet' */ ];
```
- Cada field = `{ key, label, kind }` copiado literal do DB (label pt-BR exato do seed):
  - kind TEXT → input texto; CIVIL_DATE → input date; SINGLE_SELECT → select com as opções de `custom_field_options` (COREN categoria: Enfermeiro / Técnico de Enfermagem / Auxiliar de Enfermagem).
- Todo documento tem o campo base `identifier_value` (obrigatório, rótulo "Número") — no DB é a coluna `documents.identifier_value`; CPF e PIS validam regex `^[0-9]{11}$`. `document_date` (Data do documento) e `notes` (Observações) ficam como opcionais no fim do form.
- Toda conta tem os campos base da tabela `bills`: titular impresso, endereço impresso, referência, competência (mês/ano), valor + moeda — mais os campos custom por tipo.

**Mudança (UI):**
- Select de documento: os 21 tipos reais (remover "Outro"). Select de conta: só Luz/Água/Internet (remover Gás, Telefone, Outro).
- O formulário "Preencher manualmente" renderiza os campos do tipo selecionado (re-render on change).
- Cada linha na strip: título = label do tipo + identifier_value (ex.: "CNH — 01234567890"); subtítulo = campos custom preenchidos resumidos (ex.: "categoria B · validade 08/2030 · DETRAN-SP").
- OCR mock preenche os MESMOS campos do catálogo: CNH detectada → número/categoria/emissão/validade/emissor/UF; conta de luz → concessionária/UC/NF/emissão/vencimento.
- Na revisão (passo 3), cada documento/conta lista todos os seus campos (base + custom), com labels do DB.

**Validação:**
- Trocar o tipo no select muda os campos do formulário (screenshot RG → CNH → Certidão de nascimento).
- CPF com 10 dígitos → erro de validação (regex do DB); com 11 → aceita.
- Adicionar 1 doc manual + 1 conta manual + 1 via OCR; cada linha da strip e da revisão mostra os campos específicos do tipo.
